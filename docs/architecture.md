# 架构：为什么四个层都要

这个项目最后落在四个层级上。不是"哪个更好"的问题，是**每一层能拿到的东西不一样**。

---

## 一、四层结构

```
L0  DNS / hosts     改一行配置      → 只能看到域名，反GEO里没用
L1  代理不解密      系统代理        → 域名 + 流量大小，仍然没用
L2  MITM 解密       根证书 + 代理    → 完整 SSE/JSON，含 rag snippet
L3  浏览器插件      装扩展          → 渲染出来的 DOM，含来源卡片摘要
```

L0/L1 对"反GEO"基本无意义 —— AI 平台就那十几个域名，看到 `perplexity.ai` 有流量说明不了任何事。

---

## 二、一个必须先说破的事实

很多人以为"劫持网络就能阻止投毒"。**对主流平台不成立。**

```
你 ──→ 平台（请求："2026医疗器械供应商哪家好"）
平台 ──→ 内容农场（服务器侧抓取，你看不到）
平台 ──→ 你（SSE 流，答案 + citations + rag snippet）
       ↑ 你只能劫持这一段
```

检索发生在**平台的服务器上**，不在你机器上。所以 L2 的"阻断"只是**把平台已经返回给你的答案改写一遍**，不是阻止污染进入模型。

真要阻断，得自己做检索层 —— 那是另一个产品（本地 RAG），不是代理也不是插件。

**所以 L2 和 L3 一样，本质都是事后审计。** 这一点必须先承认，否则整个设计会建立在错误的前提上。

---

## 三、L2 真正的增量

### ① citations 是结构化的

插件里为处理 Google 的 `/url?q=` 和 Bing 的 `/ck/a` base64 写的那些跳转解析，L2 完全不需要。拿到的直接是:

```json
{"web_results": [{"url": "https://...", "name": "...", "snippet": "..."}]}
```

### ② 能看到 rag snippet —— 这是质变

这是决定性的一条:

| 层 | 能看到 | 问题 |
|---|---|---|
| L3 (DOM) | 引用 URL + **平台愿意展示的**来源卡片摘要 | 摘要可能是摘要的摘要；投毒文案被截断 |
| L2 (SSE) | 引用 URL + **模型实际读进去的**那段文本 | 无 |

模型吃进去的是 snippet，不是整页。拿整页算 SimHash，测的是"站点长什么样"；拿 snippet 算，测的才是"模型被喂了什么"。

实测差距（`test/external-source.test.mjs`）:

```
不用 snippet：污染度  5  → 判绿，**完全漏报**
用上 snippet：污染度 71  → 判红，命中"摘要里含指令型话术"
```

**同一份数据，只因为多了一层 snippet，从"看起来没问题"变成"铁证"。**

### ③ 能看到模型读过但没展示的来源

模型读了 8 个页面，只给你展示 3 个引用。剩下 5 个里有没有投毒源？

DOM 永远不知道。L2 知道。插件会把这类来源单独列出来:「另有 N 条来源模型读过、但没展示给你」。

## 四、L2 的真实代价

| 坑 | 影响 |
|---|---|
| **根证书** | 必须装进系统信任链。iOS 要装 profile + 手动完全信任，Android 14+ 要改 APK。**这是劝退级的门槛** |
| **Cert Pinning** | ChatGPT / 豆包 App 大量用 pinning，MITM 直接被拒。"覆盖 App"这条大概率拿不到 |
| **HTTP/3 (QUIC)** | AI 平台几乎都上 h3。mitmproxy 支持还是实验性的，实践中得 `--disable-quic` |
| **改包会崩** | 在 JSON 里插警告 → 前端 schema 校验失败。**只能读不能写**，展示还得回到 UI 层 |
| **维护半径** | 插件坏一个站点改一个选择器；代理坏一个平台要重新解析 SSE 协议 |

**结论：L2 只能当"数据更好的取数器"，展示层必须是 L3。**

## 五、所以最终架构

```
        ┌─────────────────────────────────────┐
        │  浏览器 / App                        │
        └──────────┬──────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │  mitmproxy :8080    │  ← 可选，不装也能用
        │  antigeo_addon.py   │
        │  · 只读，绝不改包     │
        │  · 递归猜字段         │
        │  · SSE 增量解析       │
        └──────────┬──────────┘
                   │ 内存 ring buffer（最近 3 分钟）
        ┌──────────▼──────────┐
        │  HTTP :8765/recent  │
        └──────────┬──────────┘
                   │ 插件 background fetch（1.5s 超时）
        ┌──────────▼──────────────────────────────┐
        │  Chrome 插件                              │
        │  ┌────────────────────────────────────┐  │
        │  │ 统一检测引擎（一份代码）             │  │
        │  │  simhash · snippet · domains ·      │  │
        │  │  scoring                            │  │
        │  └────────────────────────────────────┘  │
        │  数据源优先级：                            │
        │  代理 snippet  >  DOM 来源卡片摘要         │
        └──────────┬──────────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │  页面旁注 + 证据卡    │  ← 展示只能在 UI 层
        └─────────────────────┘
```

**关键设计：检测引擎只有一份（JS），L2 只负责取数。**

这样不会出现"Python 一套评分、JS 一套评分，结果对不上"的经典问题。

## 六、三种部署形态

### 形态 A：只用插件（默认，零配置）

```
浏览器 ──→ 平台
     ↑
  插件读 DOM
```

- 能检测：站群模板、隐藏注入、域名形态、来源卡片摘要里的指令话术
- 不能检测：模型读过但没展示的来源、被截断的投毒文案
- 适合：**给普通人用**。点一下就好。

### 形态 B：代理 + 插件（推荐给技术用户）

```
浏览器 ──→ mitmproxy ──→ 平台
              │
              └──→ 插件（数据更全）
```

- 增加：rag snippet、未展示来源
- 代价：根证书、QUIC 处理、App 基本用不了
- 适合：**自己用 / 给小团队用**

### 形态 C：只用代理 + 命令行看报告（无插件）

```bash
mitmdump -s tools/antigeo_addon.py -p 8080
# 另开一个终端
watch -n 2 'curl -s http://127.0.0.1:8765/recent | jq ".sources[] | {host, snippet}"'
```

- 适合：**做研究 / 批量抓数据**

## 七、数据流细节

### 代理侧

```
请求进入 → 命中 AI_HOSTS? → 建 SSE collector
响应头   → content-type 含 event-stream? → 挂 stream 回调
响应体   → 只读解析：
             ① 尝试 json.loads 整段
             ② 失败则按 data: 行逐条解析（SSE 片段常不完整）
             ③ 再失败则正则扫 URL（兜底，无 snippet）
         → harvest() 递归找 {url, title, snippet}
         → STATE.merge() 去重、保留更长的 snippet、3 分钟过期
```

**递归 harvest 是关键**：不硬编码字段路径，`web_results` / `sources` / `citations` / `data.references` 全都能抓。平台改字段名不会死。

### 插件侧

```
scan()
 ├─ 找容器（反向定位：从外链向上找公共祖先）
 ├─ 收集引用（URL + 来源卡片摘要）
 ├─ 轻量分析（deep=false）→ 立刻出横条
 └─ 稳定 2.2s 后深度分析（deep=true）
      └─ background:
           ├─ fetch /recent（1.5s 超时，失败就用 DOM 的）
           ├─ 合并 snippet（代理优先）
           ├─ 抓页面（最多 6 个，4 并发）
           └─ scoreCitations()
```

## 八、如果将来要做"真正的阻断"

唯一可行的方向是**自建检索层**:

```
你的问题 → 你自己检索（过滤投毒源）→ 你自己喂给模型 → 答案
```

这和现在这个项目是两条路。当前项目是"审计别人给的答案"，自建检索是"不信任任何人给的答案"。

哪天要做，现在的 `simhash / snippet / scoring / domains` 四个模块可以直接搬过去当过滤引擎用 —— 它们不依赖 DOM，也不依赖代理。
